# ADR 0008 — Transactions and the workspace lock follow spec gate-1.5: `.local/`, an intent journal, a hash check before applying

- **Status:** accepted (rework of US-L0-03, US-L0-10, US-L0-11 for spec gate-1.5, decisions D-45
  and D-46). It supersedes ADR 0006 #1, #3 to #7 and #10, and amends ADR 0005 #4, #6, #13, #14 and
  ADR 0007 #3 to #11 (each of those ADRs has a dated amendment that points here).
- **Delivery:** in two pull requests. R1 (`.local/` paths, lock outcomes, reason tokens, US-L0-03
  details: #1 to #3, #9, #10, #11 without the `recovery` shape, #12, #14, #15) lands first and
  keeps ADR 0006's undo journal, at its new path in `.local/journal/`. R2 lands #4 to #8, the
  `recovery` shape of #11, and #13; until R2 merges, ADR 0006 #1 and #3 to #7 still describe
  the code.
- **Date:** 2026-11-27
- **Stories:** US-L0-03 (AT-h, AT-i, counts), US-L0-10 (AT-c, definitions), US-L0-11 (AT-c, AT-d,
  definitions); SPEC §5.0.6, file-format §2, §9.1, §10, commands.md §1.1 and §2.

## Context

ADR 0006 and 0007 were written before the spec said where a journal and a lock live, or how
recovery reports. They put both in `.cache/`, used an undo journal (recovery always went back to
the state before), and reported `recovery` and `staleLock` as objects of our own design. Gate-1.5
settles these points:

- `.cache/` may be deleted at any time and loses nothing. The lock, its holder record and the
  journal live in a new gitignored `.local/` (file-format §9.1). `.local/lock` is empty and
  permanent; NoteCraft creates it when missing, because a fresh clone has none.
- The transaction protocol is fixed (SPEC §5.0.6): take the lock and write `lock.json`; check that
  every target still has the content hash the engine last read, else `conflict`; write each new
  content to a temporary file beside its target and flush it; write
  `.local/journal/<txid>.json` and flush it, which is the commit point; apply the operations, then
  delete the journal, remove `lock.json` and release. On open a journal is **replayed**. A temporary
  without a journal is deleted. A target that is neither "before" nor "after" is left untouched,
  listed in `recovery.failed`, and the workspace opens read-only (`readOnlyReason: "recovery"`).
- `workspace.open` returns `{workspace, name, path, readOnly, readOnlyReason?, conflicts,
  recovery?, staleLock}`: `recovery` is `{replayed, rolledBack, failed: [path]}` and is present only
  when a journal was found; `staleLock` is a boolean. `disabled` (reason `locked`) carries
  `details.holder`. `read_only` carries `details.reason` in `requested`, `newerFormat`,
  `recovery`, `noLock`, `oversized`.
- No advisory lock → the workspace opens read-only (`noLock`), not `disabled`.
- The tree hash covers the relative path and bytes of every file under `notecraft/` except
  `.cache/` and `.local/`.
- US-L0-03: a blank `name` is absent and a given name is stored trimmed (AT-h); a `notecraft` file,
  or a non-empty folder without `workspace.json`, is `invalid_params`, and an empty `notecraft/`
  is used as is (AT-i); before the index exists, the trash check reads at most 64 KiB of front
  matter and an unreadable front matter counts as not trashed.

Nothing has been released, so no workspace on disk needs a migration.

## Decisions

| # | Decision | Reason |
|---|---|---|
| 1 | **`.local/` holds the machine-local state.** `.local/lock` (empty, permanent, only ever locked), `.local/lock.json` (the holder record) and `.local/journal/<txid>.json`. The `.gitignore` that `workspace.create` writes is `.cache/` then `.local/`, one per line. `create` still writes an empty `.local/lock` in its staging folder; the first writer creates `.local/` and the lock file when they are missing (a fresh clone), with the rules ADR 0007 #4 and #10 gave `.cache/`: `.local` must be a real folder that is a direct child of the canonical workspace folder (checked by `symlink_metadata`, never followed), a concurrent creation is not an error, and NoteCraft never deletes `.local/`, the lock file or anything in `.local/` that it did not write. **Nothing the store needs lives in `.cache/` any more**: the lock, the record and the journal never go there, and the sweep (#8) does not clean it. Files that earlier development builds left in `.cache/journal/` or `.cache/lock*` are ignored (nothing was released). | file-format §9.1, D-45. Moving the lock out of `.cache/` keeps the persistent-file decision of ADR 0007 (amended in round 3), which is what made the lock race-free on macOS and Windows. |
| 2 | **Reserved first segments: `.cache` and `.local`**, in any ASCII case. A staged write or remove whose first segment is either fails with `io` (`details.reason: "reserved"`, `details.path`) before anything is read or written. | ADR 0006 #8, extended: a command must not forge a journal, unlock a writer or delete the lock file. |
| 3 | **The tree hash** of AT-L0-10-b and AT-L0-03-d is the SHA-256 over the sorted (relative path, bytes) of every regular file under `notecraft/` except `.cache/` and `.local/` (folders are ignored, as Git ignores them). | US-L0-10 definitions. A test that used the old hash (which included `.cache/`) to notice a journal change asserts the journal files directly instead, so no check is lost (rule 31). |
| 4 | **Hash before apply.** The session keeps `seen`: workspace path → digest of the bytes it last read or wrote there, or "absent". Every read through the session's `Files` (handlers through `Ctx`, undo and redo checks, the plan) records it; every committed change records its after state; `install` (open, create, close) clears it; recovery forgets the paths it touched. Under the lock, before anything is staged, the commit compares each target's current digest (the plan's read) with the `seen` entry recorded before that read. A difference is `conflict` (`details.path`, `details.reason: "changed"`): nothing is written and no undo step is pushed. A target the session never saw is a blind write and is accepted: the plan's own read, under the lock, is its baseline. | SPEC §5.0.6 step 2 and US-L0-11 definitions. With one engine per process, a session's knowledge of a file can be stale when another process wrote it in between; the lock alone serialises writes but does not refresh that knowledge (ADR 0007, consequences). In L0 handlers read and write in one command, so the check bites only on what an earlier command read; L1's in-memory pages make it the main guard. |
| 5 | **The protocol** (replaces ADR 0006 #1, #4). All under the lock (#9). (a) Plan: read each staged path, drop changes whose bytes are equal, run the hash check (#4). (b) One remaining change: `craft_atomic::atomic_write` or a remove, as before, with no journal: one rename is already the commit point, so the outcome equals the protocol's (ADR 0006 #2 kept). (c) Two or more changes through a journaled port: **stage** each write as a new temporary beside its target, named by `craft_atomic::temp_name` (`.<name>.<pid>-<n>.craft_tmp`), created with `create_new`, written and flushed (`craft_atomic::sync_file`); parent folders are created here. (d) Write the journal with `atomic_write`: this is the **commit point**. (e) Apply in order: rename each temporary over its target (`craft_atomic::retry_rename`, then flush the folder) and remove each deleted target (then flush the folder). (f) Remove the journal, best effort. Success is returned once (e) is done: a failure in (f) leaves a journal whose targets all hold their "after" bytes, which the next lock holder removes (#6); the session sets its pending flag so its own next command does it first. | SPEC §5.0.6. Temporaries next to their targets keep each rename on one volume. The store composes craft-atomic's public pieces (`temp_name`, `sync_file`, `retry_rename`, `RealFs::sync_dir`) because craft-atomic has no two-phase write; a staged-write API in craft-libs is a later PR of its own (rule 9). |
| 6 | **Recovery replays** (replaces ADR 0006 #6). It runs only while the lock is held: in a read-write open inside the write root, and before the handler of every mutating command, undo and redo when a journal exists (ADR 0007 #7). Journals are the regular files of `.local/journal/` named `<26-char id>.json`, at most 1,000, taken in name order (ids sort by time); other entries are left alone. For each journal, each operation is decided by the digest of its target now: **after** → skipped (a leftover temporary of it goes in the sweep); **before**, and the temporary exists, is a regular file and has the "after" digest → renamed over the target (a delete: removed); **anything else** (neither digest, the temporary missing, unreadable or not matching) → the target is left untouched and listed in `failed`. Operations are independent, so the others are still replayed. A journal with no failure is removed. A journal with a failure is **kept**, with its temporaries, and later journals are not touched. A journal that cannot be read, is corrupt (codec bounds of #7) or comes from a newer format writes nothing and lists its own path in `failed`. Any `failed` path makes the workspace read-only with reason `recovery`. The way out is the user's: put the file back or remove the journal, then reopen. | SPEC §5.0.6 and AT-L0-10-c. Keeping a failed journal keeps the only copy of the "after" bytes of the file that could not be replayed (never crash, never lose data). Replay is idempotent, so a crash during recovery is recovered by the next open. |
| 7 | **Journal format** (replaces ADR 0006 #5). Canonical JSON (file-format §8): `{"format": "notecraft-journal1", "txid": "<id>", "command": "<id>", "ops": [{"op": "write", "path": "<RelPath>", "temp": "<RelPath>", "before": "<sha256>" \| null, "after": "<sha256>"}, {"op": "delete", "path": "<RelPath>", "before": "<sha256>", "after": null}]}`. `txid` is a new `model` id, and the file name is `<txid>.json`. Bounds: at most 4 MiB, at most 100,000 operations, paths unique and valid `RelPath`s outside the reserved segments, a `temp` in the same folder as its `path` with a craft-atomic temporary name, digests of 64 lower-case hex characters; anything else is corrupt. The family number stays 1: no journal of the ADR 0006 shape was ever released, and it lived in another folder. | file-format §9.1 lists each operation with its target and both hashes; the `temp` field is what replay needs. The `temp` rule stops a planted journal from renaming an arbitrary file over a target. |
| 8 | **The sweep** (amends ADR 0006 #10). It runs after recovery, under the lock, only on a handle that may write. It removes craft-atomic temporaries that no remaining journal names, and keeps every temporary when a remaining journal cannot be parsed. It walks the workspace folder (not `.git`, links never followed, the old bounds), so it also removes the temporaries of a journal write that never completed; it removes no other file in `.local/` or `.cache/`. Staging folders of a killed `create` are handled as before. | Temporaries without a journal are uncommitted transactions (SPEC §5.0.6, "rollback"). A temporary named by a kept journal holds bytes recovery may still need. |
| 9 | **The lock** (amends ADR 0007 #3 to #6). OS advisory lock on `.local/lock` through `File::try_lock`, held for one mutating command (one transaction), as ADR 0007 #1 decided. The record `.local/lock.json` is `{"process": "app" \| "cli" \| "mcp", "pid": <u32>, "host": <text> \| null, "since": "<RFC 3339 UTC>" \| null}` plus a final newline. `process` comes from `Session::set_process` (default `app`; the CLI and MCP entry points, US-L0-05 and US-L0-06, set theirs). `host` is written as `null` in L0 (#14). `since` is the clock's time formatted with `chrono` (no `clock` feature), `null` when the clock fails. Reading stays tolerant and total: a `process` other than the three is `null`, `host` is clipped to 255 bytes on a character boundary, `since` is kept only when it parses as RFC 3339, unknown keys are ignored, garbage is an unknown holder. Stale detection is unchanged: a record found once the OS lock is taken. | file-format §9.1. The record is advisory; the OS lock is the truth. |
| 10 | **Lock outcomes** (amends ADR 0007 #8 to #11). *Mutating command, undo, redo:* wait up to `LOCK_WAIT` (5 s; `Session::set_lock_wait` stays), then `disabled` with `details.reason: "locked"` and `details.holder` (the record as #9, or `null`); `details.cause` is gone. A lock the file system cannot give (`Unsupported`, `ENOLCK`) makes the session read-only with reason `noLock` and the command returns `read_only` (`details.reason: "noLock"`); other lock failures stay `io` (`details.reason: "lock"`, `details.path`). *Read-write open inside the write root:* **one try, no wait.** Taken: stale check, recovery, sweep, release. Busy: the holder is alive and its journal is its own, so the open goes on read-write with no recovery and no sweep, and the next command waits for the lock as usual. `Unsupported`, or any failure to create, open or lock `.local/lock` (a read-only medium, a `.local` that is a file or a link): the workspace opens **read-only with `readOnlyReason: "noLock"`** and nothing is written. `workspace.open` therefore never returns `disabled` or a lock `io`. A read-only or unwritable open never takes the lock. On wasm32, the lock is `Unsupported` at once, as before. | AT-L0-11-c, AT-L0-11-d, commands.md §2 (the errors of `workspace.open` are `not_found`, `corrupt`, `outside_roots`). Not waiting at open means a busy writer never delays an open, and a live holder is never mistaken for a crashed one. |
| 11 | **Open result.** `{workspace, name, path, readOnly, readOnlyReason?, notice, format, conflicts, recovery?, staleLock}`. Optional keys are left out when they do not apply (not `null`). `staleLock` is `true` only when this open found and cleared a stale record. `recovery` is present only when at least one journal was found: `replayed` counts the operations recovery applied, `rolledBack` counts the temporaries of uncommitted transactions the sweep removed, `failed` lists workspace paths (targets, or a journal's own path), at most 1,000, in journal order. When the open may not write (read-only on request, newer format, outside the write root, `noLock`) a journal is not replayed: `recovery` is then `{replayed: 0, rolledBack: 0, failed: [every target the journals name, or the journal path]}` and `notice` says that an interrupted change was not applied. A busy lock at open reads no journal, so `recovery` is absent. `notice` and `format` are kept from ADR 0005. | commands.md §2. Rule 15: a read-only view of a half-applied workspace must say so. |
| 12 | **Reason tokens.** `readOnlyReason` (open and `workspace.info`) and `read_only`'s `details.reason` use `requested`, `newerFormat`, `recovery`, `noLock` (`oversized` arrives with L1 items). `store::ReadOnlyReason` gains `NoLock`. A failed in-session recovery (#6) makes the session read-only with reason `recovery` and the command returns `read_only`; the `io` reason `recovery_pending` of ADR 0006 #7 is no longer returned. | commands.md §1.1. One vocabulary on every surface. |
| 13 | **A failure during a live commit** (replaces the rollback of ADR 0006 #4). Before the commit point: the temporaries are removed (best effort; the sweep removes the rest), the error is returned, the tree hash is unchanged. After it (an apply step fails or panics): the session rolls back with a **compensating transaction** built from the bytes it already holds for undo: it stages the "before" bytes, writes a new journal whose operations take each target from the original "after" back to "before", removes the original journal, applies, then removes the new journal. A crash anywhere in this sequence still recovers to one side: with both journals present, replay in id order goes forward then back. If the compensating journal cannot be written, the original stays, the pending flag is set, and the error is `io` with `details.unrestored`; the next recovery (command or open) then completes the original change, and the message says so (rule 15). | SPEC §5.0.2 asks a failed command to leave memory and disk unchanged; SPEC §5.0.6 makes a journal replay forward. Restoring files from memory while a forward journal exists would leave targets at "before" with their temporaries gone, which replay could never finish. A compensating journal uses the same proven path. |
| 14 | **`host` is `null` in L0.** | The standard library has no portable host-name call; reading it needs a new dependency or `unsafe` (forbidden). A host name is also a personal detail that would travel in `details.holder` to CLI and MCP output (rule 20). The record is advisory and its readers accept a string, so writing one later is reversible. Open point for the spec room. |
| 15 | **US-L0-03 details** (amends ADR 0005 #4, #13, #14). A `name` that is empty or only whitespace is absent: the default of ADR 0005 #14 applies; any other name is stored trimmed; the 1,000-character bound applies to the parameter as given. The refusals of ADR 0005 #4 already match AT-L0-03-i (`not_a_folder`, `folder_not_empty`, `workspace_exists`); an empty `notecraft/` is still replaced by the built tree (remove, then rename), so the result is all or nothing; an empty folder that cannot be removed (a mount point) gives `io`. Counts: a page whose file cannot be opened or read is counted as not trashed (it no longer makes the whole count `null`); a front matter that does not close within 64 KiB is not trashed; an unreadable folder still makes the count `null`. | AT-L0-03-h, AT-L0-03-i and the "Counts" note of US-L0-03 (D-46). |

## Consequences

- `store` API: `LOCAL_DIR`, `LOCK_FILE` (`.local/lock`), `LOCK_RECORD` (`.local/lock.json`),
  `JOURNAL_DIR` (`.local/journal`) and a journal path function replace `JOURNAL_HEAD` and
  `journal_blob`; `Journal` and its operations change shape (#7); `Holder` becomes `{process, pid,
  host, since}`; `ReadOnlyReason::NoLock`; the workspace gains staged writes, renames and a
  bounded journal listing; `is_reserved` covers `.local`.
- `engine` API: `Files` gains `stage`, `rename` and a journal listing, with defaults written on
  `write`, `read` and `remove` so the US-L0-02 test ports keep working unchanged;
  `Session::set_process`; the session's `seen` map; open-result and error-detail changes (#10 to
  #12). The catalog row F-CMD-11 is unchanged.
- A command that changes `n ≥ 2` files costs about `2n + 2` file operations plus folder flushes
  (staged temporaries, the journal, the renames or removes, the journal removal); the before
  bytes are not written any more. A one-file command costs what it did, plus the hash check of
  its target, which the plan's read already provides.
- Many existing tests change: ADR 0006's tests assumed recovery goes back to the state before;
  they now assume it goes forward after the commit point. The list, test by test, is in the
  rework's TASKS.md. Removing or weakening a check is not allowed (rule 31): each test keeps the
  strength of its oracle or gains one.
- AT-L0-11-d cannot be run on a real file system without locks in CI. The test uses the cases
  #10 maps to the same path (a `.local` that is a file, a read-only medium); a unit test covers
  the `Unsupported` and `ENOLCK` mapping.
- Carry-overs to L1: a page move renames folders, so the journal needs a `rename` operation for
  folders; digests of temporaries and targets over 4 MiB (attachments) must be streamed; the
  `seen` map becomes the index's revisions; the cache rebuild may delete `.cache/` freely but never
  touches `.local/`; MCP `batch` is one transaction under one lock and one journal.
- Workspaces made by development builds before this change have a `.gitignore` without `.local/`
  and a `.cache/lock`. Opening never rewrites `.gitignore` (AT-L0-03-d); nothing was released, so
  no repair command is planned.
- `docs/architecture.md` and `docs/gaps.md` are updated with the code, not before it.
